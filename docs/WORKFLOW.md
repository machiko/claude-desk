# 開發流程（desk 工作桌）

> 一句話：**你只在四個時間點出手：拍板規格、處理卡住的流程、合併 PR、打 tag 上線。中間「實作 → 測試 → 驗收 → 修正」由 AI 與機器自動走完，自動修正整張卡最多兩輪；每張卡只審查一次，卡片之間的交互留給發版前的整版審查。**

第一次用先輸入 `/desk tutorial`，在沙盒裡把下面的六段實際走一遍。

## 角色

| 角色 | 負責 | 不做 |
|---|---|---|
| 主控台對話（開著 `/desk` 的那個 Claude Code 對話） | 規格、完成檢查、關卡判定、兩次失敗後的診斷 | 不在主 repo 切分支、不 push |
| Agent（`claude --bg`，在各 worktree） | 實作到完成檢查綠、寫回 DESK 卡、`.task/REPORT.md`；被要求時（含合併段派的推送 Agent）push 自己的分支、開 PR；合併段自動派的解衝突 Agent 把基準分支合併進來（不 push） | 不問問題等人（寫進卡的「等你」後結束）、不 force push、不推別的分支、不合併 PR、不上線 |
| 審查對話（新對話、不接續 Agent） | 只看任務檔、自己重新執行完成檢查（desk 已在同一個 HEAD 跑過並通過時只跑相關測試）、看 diff | 不啟動容器、不改 port、不參考 Agent 的結論 |
| 你 | 業務決策、合併、打 tag、部署；push、開 PR 在面板按「⇡ 開 PR」「⇡ push」派 Agent 做（專案設了 `autoPr` 時審查過關自動派，高風險改動照舊等你看） | — |

## 六段

| 段落 | 白話 | 誰開始 | 誰做事 | 誰判定過關 | desk 怎麼知道 |
|---|---|---|---|---|---|
| 1 規格 | 決定做什麼、怎樣算完成 | 你提需求 | `/desk:card spec` 寫目標、非目標、驗收情境與測試 | 你 | 卡片有 `檢查`、沒有「等你」與 `spec：` 關卡 |
| 2 實作 | 寫程式 | 你按 `g` | Agent（`claude --bg`） | 交給下一段 | Agent 執行中 |
| 3 測試 | 測試 exit 0 | 自動 | 機器 | 機器（exit code） | desk 執行過且通過、之後沒有新 commit |
| 4 驗收 | 新對話做 code review，自己重新執行測試（desk 剛在同一個 HEAD 測過就只跑相關測試） | 自動 | Claude 新對話 | 數字：CRITICAL＋HIGH＝0，影響行為的 MEDIUM 寫進「等你」 | 卡片 `review：CRITICAL n、HIGH n…` |
| 5 合併 | push、開 PR、CI、按合併 | 你按「⇡ 開 PR」／「⇡ push」（按兩次）；專案設了 `autoPr` 時驗收過關後自動派（高風險照舊等你） | 推送 Agent push、開 PR（依 origin：GitHub `gh pr create`、Bitbucket MCP `bb_post`、其他只 push 留網址，或專案 `pr.open` 指定指令）；CI | 你按合併 | Bitbucket（MCP `bb_get`）或 GitHub（`gh pr list`）唯讀讀 PR 與 CI；都讀不到時看 git：驗收過後分支 HEAD 經由 merge commit 併進基準分支就算合併（squash、rebase、fast-forward 合併看不出來，要靠 PR 狀態）；fetch 基準分支後用 `git merge-tree` 試合併，有衝突標 ✕「與 main 有衝突」 |
| 6 上線 | 打 tag、部署、部署後步驟 | 你按「⚑ 發版」交給對話 | 對話照發版步驟做、你的部署流程 | 你按 `u` 確認上線 | commit 在 `v*` tag 裡＝待確認；按 `u` 清掉 `release：` 關卡＝完成 |

發版線（`release/*` 分支本身）只看「測試」與「上線」兩段。

## 自動流程（第 2–4 段）

1. 你按 `g` 開始一輪。`g` 本來就按兩次；這張卡的測試還沒核准過時，第一次按會在測試列列出指令全文，第二次按就核准它並派工（不跳對話框）；之後同一張卡、同一條指令不用再核准。按 `t` 確認規格的卡，確認時就核准了。`/desk go` 遇到沒核准的測試不派，回一句請你到面板按兩次。Agent 做完 → desk 自動執行測試。
   - 流程停在測試段時（Agent 把測試指令改了、容器沒啟動、測試中斷），「▶ 輪到你」寫原因；排除後按 `v`（指令改過的測試列直接列出新指令，按兩次 `v` 核准並執行），測試跑完流程接著走。沒有暫停中的流程時，`v` 只跑測試、記結果。
2. 測試紅 → 自動派「修正」；測試綠 → 自動派驗收（新對話）。
3. 驗收有 CRITICAL 或 HIGH → 同一輪自動派「依 .task/REVIEW.md 修正」（資安驗收依 .task/SECURITY.md），修完只重新測試：綠了就過關、不複審，面板寫「已修正・未重新驗收」（高風險改動照舊回到 1 複審並跑資安審查）；沒有 CRITICAL／HIGH → 過關，提醒你開 PR；專案設了 `autoPr` 時改成自動派推送 Agent 開 PR（PR 已開只 push，已是最新就不派），合併仍由你按。只關於規格紀錄、文件、命名、重複這類不影響行為的 MEDIUM，驗收直接記在審查檔（記錄、不修）與卡片 History、不修也不問你；可能影響行為的 MEDIUM 不自動修，審查標「（等你決定）」、過關時寫進「等你」讓你選不修／另開卡修（推薦）／修掉／改規格。你在面板選 B) 另開卡修送出時，對話開一張疊在這條分支上的後續卡（卡名「<原卡名>：審查 MEDIUM」）、把要修的 MEDIUM 寫進新卡，原卡不派修正、照常往開 PR 走；後續卡的卡片多一欄「疊放於」，原卡合併前只能寫、確認規格，不派工，合併（或原卡歸檔）後自動派實作、先把基準分支 merge 進來（見 [/desk:card](../skills/card/SKILL.md) 的 new）。選 C) 修掉送出、對話清掉「等你」後，工作桌自動派修正（算一輪修正，不受上限擋），修完自動重新測試，一般風險綠了就過關、不重新驗收。
4. 自動修正最多兩輪，算整張卡（同一條分支）的總數，測試與驗收共用；重新驗收、按 g／w 重開都不歸零，換分支才從 0 起算。用完仍有 CRITICAL／HIGH 或測試沒過就暫停，摘要列亮「● 等你」，動態寫「整張卡已自動修 2 輪仍有…」，你選開 PR、按 g 再修一輪（照樣算進總數）或改規格。
5. 驗收通過後分支又有新 commit（例如你決定 MEDIUM 現在改、或在面板外改了程式）：那次驗收不算數，六段退回「測試」，流程自動重新測試，綠了就過關、不重新驗收（面板寫「測試通過・未重新驗收」）；高風險改動照舊重新驗收（只看上次驗收之後的 diff）。不另起一輪修正數（整張卡的累計照帶）。只寫回卡片、沒有 commit 的決定不會退回。
6. 驗收過關、還沒合併的分支跟基準分支（PR 目標，沒有就是卡片的「基準」欄、release 線、`card.base` 或 origin/HEAD）有衝突：desk 在合併段 fetch 那個基準分支（只更新遠端追蹤分支，每個 worktree 最多 5 分鐘一次，按 `r` 例外），再用 `git merge-tree` 試合併，不動工作區。有衝突時自動派「解衝突」Agent：把基準分支 merge 進來（不 rebase、不 force push、不 push）、解衝突、跑測試、commit；要業務判斷就放棄合併、寫進「等你」。之後照第 5 點自動重新測試；高風險改動重新驗收時不審基準分支帶進來的改動、改看衝突怎麼解（`git log -p --remerge-diff`）。同一個 HEAD 只自動試一次；流程是別的對話開的、沒有自動流程、流程已暫停、高風險改動、worktree 有未提交的改動、試過一次沒解開時不派，「輪到你」寫原因，在對話合併、解衝突並 commit。落後但沒衝突不合併。專案設了 `autoPr` 時，過關當下先照第 3 點自動派推送，推送 Agent 做完才試合併、派解衝突（同一個 worktree 一次只派一個 Agent）；合併 commit 重新驗收過關後再照 `autoPr` 自動 push。
7. 流程碰不到合併與上線（把基準分支合併進分支不算合併 PR）；合併段派的推送 Agent（push、開 PR；含設了 `autoPr` 時過關自動派的）與解衝突 Agent 做完不跑測試、不派驗收、不算修正輪。自動派的推送名額滿了照樣排隊，取消排隊或沒派出不會讓流程暫停。
8. 額度煞車：5 小時額度剩餘低於門檻（`dispatch.json` 的 `chainQuotaStop`，預設 30%）時，流程停在派下一個 Agent（修正、驗收、資安驗收、解衝突、`autoPr` 推送，含排隊中的）之前：不派、流程暫停，動態、提示與通知寫剩多少、門檻與重置時間；重置後按 `g` 重開；解衝突被擋時合併段沒有 g，原因句結尾改寫「重置後在對話合併基準分支、解衝突」；擋在派驗收或資安驗收前的，按 g 直接派那次驗收接續原本那輪，不多派實作。審查檔照常歸檔、結論照記；本機的測試與只動文件的免驗收過關照跑；自動推送沒派時流程仍是過關，可自己按「⇡ 開 PR」。你手動派工不看額度，正在跑的 Agent 不停，讀不到額度（含重置時間已過、還沒更新的舊用量）時不擋。
9. 改程式的 Agent（繼續、回覆、修正、解衝突）改的過程與收尾都只跑相關的測試，整套交給 desk 做完後自動跑的那次（沒過會派修正）；驗收時 desk 已在同一個 HEAD 跑過並通過，驗收也不重跑整套、只跑相關的測試。同一個 HEAD 的整套只跑一次，也不會被好幾個 Agent 反覆同時跑。

## 讓審查越來越準

- **常犯錯誤清單**（`pitfallsPath`）：第一次審查先讀（複審、重新審查、資安審查不讀）；實作與回覆的 Agent 也先讀、逐條對照（自動修正輪與按 g 派的修正不讀，照審查檔或檢查結果修），實作、回覆與修正都在交出前自我檢查（每條驗收情境拿掉一處最關鍵的改動、只跑對應的測試要會紅，不跑整套；改到自動流程才對照 main 跑相鄰路徑的測試）。新條目由歸檔回顧提出、你確認後追加；要刪改由你手動處理。專案 `dispatch.json` 設了 `review.pitfalls` 就改用那個路徑，清單可以放進 repo 跟著走。
- **審查前置指令**（`review.preflight`）：任何會輸出候選清單的工具，審查先跑、逐條驗證；只有驗證過的才列進審查檔，第一行記前置成功（候選幾條、採用幾條）或失敗原因，失敗就照常審。設了 `review.preflightMinFiles` 時，diff 少於那麼多檔的審查與所有複審、重新審查不跑前置；規格前審的門檻是 `card.specPreflightMinFiles`（預設 3）。
- **審查存底**（`reviewsDir`）：每次審查結束，desk 把 `.task/REVIEW.md`（或 `SECURITY.md`）存一份。
- **歸檔回顧**（`card.retro`）：卡片歸檔時執行回顧指令，統計這張卡的輪數、審查次數、候選命中率與用量；回顧輸出若有候選 pitfalls，對話會提問確認後才追加到常犯錯誤清單。
- **複審只看新 diff**（高風險改動才有複審）：修正後的審查只看上次審查之後的 commit，只確認上一輪的 CRITICAL／HIGH 修好沒；標「等你決定」還沒回答的照原樣再列，已回答、已列過的 LOW 與標「不修」的不重提。

## 依改動的檔案分風險

| 風險 | 判斷 | 流程怎麼走 |
|---|---|---|
| 低 | 只動 `*.md`、`docs/`、`*.txt` | 測試通過就過關，免驗收 |
| 一般 | 其他 | 測試 → 驗收 |
| 高 | Auth／Middleware、migration、CI 設定、Dockerfile／compose、相依套件鎖檔、`.env`，加上設定檔 `risk.high` 的專案路徑 | 測試 → 驗收 → 資安驗收 → 停下來等你看過；開了 PR 就算看過。設了 `autoPr` 也不自動開 PR。設了 `review.combineSecurity` 時資安重點併進驗收，過關後不另派資安驗收，照樣停下來等你看 |

改了哪些檔＝分支相對「要併進去的分支」的 diff，基準依序找：PR 目標 → 卡片 DESK 區塊的「基準」欄（`/desk:card new` 開卡時記下的分支，疊放的後續卡記原卡的基準；有這欄就不猜最新的 release 線，分支已經不在就當沒有）→ 最新的 `origin/release/*` → 專案 `dispatch.json` 的 `card.base` → `origin/HEAD`。都找不到就算一般風險。審查看的 diff 與「⇡ 開 PR」的目標也照這個順序。

## 每天怎麼用

1. 在主控台對話輸入 `/desk`：摘要列一行看有沒有「等你」；面板看「現在」那一件，第二列寫著輪到誰、要按什麼。
2. 等你 → 在面板按選項字母 → `f` 填入決策 → Enter 送出。送出後那題鎖住，等對話照決策處理並寫回卡片；回合結束卡片還沒改，面板會提醒你開卡片改或重送。
3. footer 只列這一段該做的動作：同步只在卡片落後分支時出現；合併之後只剩發版、上線確認或歸檔（加上開啟），輸出、審查檔、PR 收進 `m`。要強制做別段的事按 `m` 展開全部。
4. 派工：`g` 繼續（開始一輪流程）、`w` 驗收、`s` 同步，都要按兩次確認；`y` 回覆停下來問的 Agent（Agent 把題目寫進「等你」的，在對話處理並把「等你」清成「無」之後，面板就不再等它回覆，Agent 不會被停掉），`k` 停止，`l` 看最近的輸出。同時最多 `maxAgents`（預設 3，整台機器一起算）個 Agent 在跑，再派的（含自動流程派的）排隊，面板寫第幾位、有空位依序派出，`k` 取消排隊。卡片下一步寫的是驗收（例如「派驗收」「按 w」）時，`g` 不派「繼續」，面板會叫你先按 `v` 執行測試、通過後按 `w`。
5. 合併後：現在卡會列出卡片「部署步驟」與歸檔指令。待辦寫進登錄表「## 提醒」：`- YYYY-MM-DD 事項` 到期前三天出現，`- 事項` 不寫日期時一直列在面板；面板收成一列，按 `m` 展開（最多 4 列）；打勾、劃掉、日期格式不對的行不算。
6. 卡片要改內容 → `o` 開啟 CARD.md。

## 在面板外做事

desk 只讀卡片與 git，看不到其他對話。git 與 PR 狀態會自動更新；卡片內容要有人寫回才會變。

- 在主對話直接開發（不按 `g` 派 Agent）也照六段走：`/desk:flow` 說明每段對話要做什麼、面板怎麼看得到、哪些要回面板按（`t`、`v`、`w`、`u`、歸檔）。
- 告一段落時 `/desk:card done <slug> <狀態一句>` 寫回卡片：狀態改成那句、History 記一筆「<人>：<狀態> → <結果>（commit <HEAD>）」；下一步依關卡寫成面板認得的一句，平常是「到面板按 v 執行測試」（面板第二列會說通過後按 w 派驗收；沒有背景流程時 v 只跑測試，驗收要自己按 w），其他三種（驗收過關後有新 commit、沒有新 commit、依審查修完未複審）見 `/desk:flow`；規格沒確認會拒絕，也不會把測試或驗收標成通過。要對話自動記得寫回，把 `/desk:flow` 末尾那一行規則貼進專案的 `CLAUDE.md`。
- 在這個對話裡改卡片、跑 `/desk:card`、`git commit` 或打 `!` 指令，面板會馬上重讀。
- 在面板選一件任務，之後的對話都以它為主（你打的每則都附上它的卡）；要取消選取，點「現在 · 你選的」那列的「✕ 取消選取」，或按 `m` 展開更多動作、點「✕ 取消選取」。
- 忘了寫：分支最近一次 commit 改到的程式比卡片新時，現在卡會提示；回到面板按 `s` 兩次同步（新對話只看卡片、`git log`、`git status`）。
- 卡片更新前先別按 `g`：繼續接的是 desk 記錄的對話，不是你另開的那個。
- 別在 Agent 的 worktree 裡同時改程式：worktree 有不是上一個 Agent 留下的未提交改動時，`g`、`y`、`w` 都拒絕並說原因，自動流程也停下；commit 或還原後再派（`s` 同步不受影響）。Agent 被 `claude stop` 停掉（或面板按 `k`）不算做完：流程暫停，看過 worktree 後按 `g` 重開。desk 自己停掉做完的 Agent（`stopDone`）不算這種：它已經記成做完，流程照常往下走。
- 要長時間手動做某件：登錄表加一欄 `Executor`，那一列寫 `manual`，desk 就只追蹤、不派工。

## 開卡與歸檔

- 開卡：`/desk:card new <分支> <卡名> [base]`（建 worktree＋DESK 卡＋登錄表列；不帶 base 從主 repo 當下的分支切出，記在卡片的「基準」欄）。
- 開卡順序：三條規則，讓 PR 之間不因共用檔互相衝突。① 改名、搬檔、改六段結構這類橫切重構單獨開卡，合併前不開其他卡的實作（已在做的卡先合，或等它合併後再 sync main）。② 同時在審查與合併段的卡不超過 4 張，過關一張就合併，不要攢著一起合。③ 功能卡不改 README 與 WORKFLOW 的功能說明段：要補的說明寫在卡片「## 規格」的目標或 Decisions，開頭標「待補文件：」，發版第 3 步一次補進去（CHANGELOG 照舊寫片段檔）。理由：2026-10 的 9 張卡並行時，README 衝突 6 次、WORKFLOW 4 次、dispatch.ts 3 次，主因是六段改名跟其他 8 張同時在做。
- 瑣事卡：只改註解、CHANGELOG、沒被測試引用的說明文字時用 `/desk:card new <分支> <卡名> --trivial` 開卡，規格一句、免前審，測試、CI 與審查風險照舊（怎麼寫規格見 /desk:card）。小卡不要一張發一版，累積到一起發（每版都要走暫存 worktree、CI、歸檔與自動更新）。
- 規格：`/desk:card spec <slug> [需求]`（讀卡與程式，有推薦的題照推薦寫成預設決定（記在 Decisions，確認規格時一起看）、沒推薦的才問，把目標／非目標／驗收情境寫進「## 規格」，關卡設 `spec：待確認規格`，此時不能派實作，只能同步：同步平常收在「更多動作」m 裡）→ 看過後在面板按兩次 `t`（或輸入 `/desk:card spec <slug> ok`）清關卡：面板按 `t` 確認後自動派實作；在對話用指令確認的，回合結束後自動派。審查會逐條對照驗收情境。確認時會列出實作計畫跟其他進行中卡片同檔的預警（`同檔預警：<檔> 也在「<卡名>」的實作計畫`，也記進 History；只預警、不擋確認），可以先排合併順序或改成疊放。
- 歸檔：上線後 `/desk:card archive <slug>`，或在面板點兩次「⌫ 歸檔」（卡、審查檔與 .task 的計畫／報告複製到歸檔資料夾、登錄表移到已歸檔段），再自己刪 worktree。另有兩種自動歸檔：發版時 CI 通過、各卡狀態寫好之後用 `/desk:card archive <slug>… --cleanup` 把發版請求列過的卡一次歸檔，已合併又乾淨的 worktree 與分支一起移除（是 `/desk:release` 確認題的最後一項動作，見下面發版段第 10 步之後）；有 `release：` 關卡的卡按兩次 `u` 確認上線後接著歸檔，worktree 與分支保留（發版線與教學那件照舊只清關卡）。卡片「## 部署步驟」有已填的步驟時，腳本與面板的完成提示會列出筆數並提醒：步驟跟著卡片歸檔，隨發版線發版的卡要先把步驟搬到發版線卡片或登錄表「## 提醒」（只提醒，不自動搬）。
- CHANGELOG：每張卡的條目寫在 `changelog.d/<slug>.md`（`- ` 開頭、動詞開頭的條目，沒有標題），Agent 的派工提示也這樣要求；不改 CHANGELOG.md，分支之間才不會搶「## 未發布」。專案的 CHANGELOG 用 Keep a Changelog 時，在專案 dispatch.json 設 `card.changelog.format = "keepachangelog"`，發版合併就改成 `## [Unreleased]`／`## [<版本>] - <日期>` 與 `### Added／Fixed…` 小節（動詞對照見 `/desk:card` 的 changelog 說明）。
- 合併到發版線：PR 目標（或 git 看到併進的分支）是 `release/*` 的卡，隨那條發版線發版：上線段寫「隨 <發版線> 發版，待打 tag」，沒有自己的「⚑ 發版」，也不列進別張卡的發版請求；發版線打了 tag、tag 包含這張卡的 HEAD 後才能歸檔。
- 發版：要發的 PR 都合併之後，在面板按兩次 z（「⚑ 發版」，上線段、還沒打 tag 的卡帶頭顯示）把一行 `/desk:release …` 短請求（所有待發版的卡與 PR、發版後要清理的卡）填進輸入框，按 Enter 送給對話；對話載入 `/desk:release`（[skills/release/SKILL.md](../skills/release/SKILL.md)）照規則做：確認方式（按兩次 z 的請求帶「已在面板確認」段）、確認題範本、照做的動作順序、失敗就停與不做的事都只寫在那裡。按兩次就算同意照慣例版號、對話不再問；手打的請求或判斷不了版號時對話才出題，你在面板按 a、b 或 c 再按 `f` 回答。面板與背景 Agent 都不打 tag。desk 的版號規則：以最新 `v*` tag 為基準，這次的卡有 `feat/`／`feature/` 分支或片段有「新增」條目就升次版號（例如 0.37.0 → 0.38.0），否則升修訂號（0.37.0 → 0.37.1）；0.27.0 起 12 次發版都符合（只看「新增」會跟 0.29.0、0.31.0、0.32.0、0.34.0、0.36.0 不合）。下面是 desk 確認後依序做的步驟，其他專案把版號檔換成自己的：
  1. 從 origin/main 開暫存 worktree，以下都在那裡做：`git fetch origin && git worktree add --detach <暫存路徑> origin/main`；接著照 `/desk:release` 的「整版審查」派一個審查 Agent 看「上一個 `v*` tag..origin/main」的整段改動（重點是卡片之間的交互），結果寫進 reviews 資料夾的 `release-v<版本>.md`，有 CRITICAL／HIGH 就停下問你、不打 tag
  2. `/desk:card changelog <版本>`：把片段合併成 `## <版本>` 段並刪掉片段檔；沒有片段、版本段已存在、片段格式錯都會報錯不改檔
  3. 補文件：讀這次發版每張卡「## 規格」的目標與 Decisions，把開頭標「待補文件：」的說明補進 README／WORKFLOW 的功能說明段（功能卡不直接改文件、集中在這一步補）；都沒有就跳過
  4. 改 `.claude-plugin/plugin.json` 的 `version` 成 `<版本>`
  5. 跑 `claude plugin validate .` 與整套測試（`claude plugin test .`、`python3 -m unittest discover -s skills/card/tests`、`python3 -m unittest discover -s scripts/tests`）
  6. commit：`git add CHANGELOG.md changelog.d .claude-plugin/plugin.json README.md docs/WORKFLOW.md && git commit -m "chore: 更新 版號為 <版本> 並整理 CHANGELOG"`
  7. 打 annotated tag：`git tag -a v<版本> -m "v<版本>"`
  8. push 主分支與 tag：`git push --atomic origin HEAD:main v<版本>`（`--atomic`：origin/main 已前進、main 被拒時 tag 也不推，不會留下不在 main 上的 tag）
  9. 等 main 的 CI 通過：先取這次 commit 的 run id（`gh run list --branch main --commit <commit> --limit 1 --json databaseId -q '.[0].databaseId'`，還沒出現就等幾秒再查），再 `gh run watch <id> --exit-status`（非互動環境一定要給 id；`--exit-status` 讓 CI 失敗時回非零）；沒有 gh 就到 GitHub Actions 看
  10. 收尾：主 repo 在 main 且沒有改動就 `git merge --ff-only origin/main`（否則跳過並寫進狀態）、`git worktree remove <暫存路徑>`，每張卡的狀態寫「已發版 <版本>：tag 與 main 已推送，main 的 CI 通過」

  發版請求列了要清理的卡（沒有 `release：` 關卡的卡）時，第 10 步寫好各卡狀態之後由對話照 `/desk:release` 在主 repo 跑 `/desk:card archive <slug>… --cleanup`，把這些卡歸檔並移除 worktree 與分支（你在題目選照做就是同意；只用 `git worktree remove`、`git branch -d`，不加 `--force`／`-D`、不碰遠端；沒併入、有未提交的改動、有被 git 忽略的本機設定或資料（`.env*`、`*.local.*` 等）或 git 拒絕的保留，原因與自己刪的指令寫進登錄表「## 提醒」；其他被忽略的檔隨 worktree 一起刪，可重建的（`node_modules`、`__pycache__` 等）以外列在輸出與提醒），沒移除的項目與原因寫進「狀態」告訴你。

  專案是 desk 自己時，題目的動作最後再多一項「更新 desk 並重載」（接在「歸檔並移除 worktree 與分支」之後；沒有要清理的卡就接在等 CI 通過之後）：由工作桌在回合結束自動跑一次 `/desk update` 並重新載入，對話不用做；本機資料夾安裝要在預設分支、沒有未提交改動與未 push 的 commit 才會更新，更新失敗（含被擋下）只在動態回報一次、不重試。

  之後你做的事：有 `release：` 關卡的卡不在這次清理，部署後按 `u` 確認上線，會接著自動歸檔（worktree 與分支保留）；其他還沒歸檔的卡照舊歸檔（面板點兩次「⌫ 歸檔」或 `/desk:card archive <slug>`）。

## 常見狀況

- **按 `g` 出現 workspace not trusted**：背景 Agent 只在「信任過的 repo」裡啟動，看的是 repo 根目錄，不是上層資料夾。面板會直接列出這三步（提示、動態與「輪到你」）。處理：開新的終端機分頁 `cd <repo 根目錄> && claude`，信任提示選 **Yes, I trust this folder**，`/exit` 離開，回面板重按 `g`。不要用 `!` 跑，`!` 沒辦法回答信任提示。派工失敗不會留下任何東西，直接重按即可。
- **任務顯示「等批准」、輪到你寫「Agent 在等權限批准」**：背景 Agent 停在權限提示（要跑某個指令或寫某個檔），面板代替不了批准，`y` 也不會出現。處理：到終端機跑 `claude agents`，選那個 Agent（名字在面板那句話裡）批准或拒絕；批准後面板會自動更新（急的話 `m` → `r`）。不想放行就按 `k` 停掉它。
- **打了 tag 但面板沒出現 `u 上線確認`**：按 `r` 重新整理，並確認卡片關卡是 `release：…`。
