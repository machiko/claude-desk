# 開發流程（desk 工作桌）

> 一句話：**你只在四個時間點出手：拍板規格、處理卡住的流程、合併 PR、打 tag 上線。中間「實作 → 檢查 → 審查 → 修正」由 AI 與機器自動走完，修正最多兩輪。**

第一次用先輸入 `/desk tutorial`，在沙盒裡把下面的六段實際走一遍。

## 角色

| 角色 | 負責 | 不做 |
|---|---|---|
| 主控台對話（開著 `/desk` 的那個 Claude Code 對話） | 規格、完成檢查、關卡判定、兩次失敗後的診斷 | 不在主 repo 切分支、不 push |
| Agent（`claude --bg`，在各 worktree） | 實作到完成檢查綠、寫回 DESK 卡、`.task/REPORT.md` | 不問問題等人（寫進卡的「等你」後結束）、不上線 |
| 審查對話（新對話、不接續 Agent） | 只看任務檔、自己重新執行完成檢查、看 diff | 不啟動容器、不改 port、不參考 Agent 的結論 |
| 你 | 業務決策、push、開 PR、合併、打 tag、部署 | — |

## 六段

| 段落 | 白話 | 誰開始 | 誰做事 | 誰判定過關 | desk 怎麼知道 |
|---|---|---|---|---|---|
| 1 規格 | 決定做什麼、怎樣算完成 | 你提需求 | `/desk:card spec` 寫目標、非目標、驗收情境與完成檢查 | 你 | 卡片有 `檢查`、沒有「等你」與 `spec：` 關卡 |
| 2 實作 | 寫程式 | 你按 `g` | Agent（`claude --bg`） | 交給下一段 | Agent 執行中 |
| 3 檢查 | 完成檢查 exit 0 | 自動 | 機器 | 機器（exit code） | desk 執行過且通過、之後沒有新 commit |
| 4 審查 | 新對話做 code review，自己重新執行檢查 | 自動 | Claude 新對話 | 數字：CRITICAL＋HIGH＝0 | 卡片 `review：CRITICAL n、HIGH n…` |
| 5 合併 | push、開 PR、CI、按合併 | 你 | CI | 你按合併 | Bitbucket（MCP `bb_get`）或 GitHub（`gh pr list`）唯讀讀 PR 與 CI；都讀不到時看 git：審查過後分支 HEAD 經由 merge commit 併進基準分支就算合併（squash、rebase、fast-forward 合併看不出來，要靠 PR 狀態） |
| 6 上線 | 打 tag、部署、部署後步驟 | 你 | 你的部署流程 | 你按 `u` 確認上線 | commit 在 `v*` tag 裡＝待確認；按 `u` 清掉 `release：` 關卡＝完成 |

發版線（`release/*` 分支本身）只看「檢查」與「上線」兩段。

## 自動流程（第 2–4 段）

1. 你按 `g` 開始一輪。這張卡的完成檢查還沒核准過，按 `g` 時就先問（列出根目錄與指令全文），選「核准並派工」才派；之後同一張卡、同一條指令不再問。Agent 做完 → desk 自動執行完成檢查。
   - 流程停在檢查段時（Agent 把檢查指令改了、容器沒啟動、檢查中斷），「▶ 輪到你」寫原因；排除後按 `v`（指令改過的會先問一次），檢查跑完流程接著走。沒有暫停中的流程時，`v` 只跑檢查、記結果。
2. 檢查紅 → 自動派「修正」；檢查綠 → 自動派審查（新對話）。
3. 審查有 CRITICAL 或 HIGH → 自動派「依 .task/REVIEW.md 修正」，回到 1；只有 MEDIUM／LOW → 過關，提醒你開 PR。
4. 修正最多兩輪（檢查與審查共用），第三次仍未通過就暫停，摘要列亮「● 等你」，動態寫原因。
5. 審查通過後分支又有新 commit（例如你決定 MEDIUM 現在改、或在面板外改了程式）：那次審查不算數，六段退回「檢查」，流程自動重新檢查、重新審查（只看上次審查之後的 diff），不算修正輪數。只寫回卡片、沒有 commit 的決定不會退回。
6. 流程碰不到合併與上線。

## 讓審查越來越準

- **常犯錯誤清單**（`pitfallsPath`）：每次審查先讀。同類問題在過去的審查紀錄出現過，審查對話會在檔尾追加；要刪改由你手動處理。
- **審查存底**（`reviewsDir`）：每次審查結束，desk 把 `.task/REVIEW.md`（或 `SECURITY.md`）存一份。
- **複審只看新 diff**：修正後的審查只看上次審查之後的 commit，已列過的 MEDIUM／LOW 不重提。

## 依改動的檔案分風險

| 風險 | 判斷 | 流程怎麼走 |
|---|---|---|
| 低 | 只動 `*.md`、`docs/`、`*.txt` | 檢查通過就過關，免審查 |
| 一般 | 其他 | 檢查 → 程式碼審查 |
| 高 | Auth／Middleware、migration、CI 設定、Dockerfile／compose、相依套件鎖檔、`.env`，加上設定檔 `risk.high` 的專案路徑 | 檢查 → 程式碼審查 → 資安審查 → 停下來等你看過；開了 PR 就算看過 |

改了哪些檔＝分支相對「要併進去的分支」的 diff，基準依序找：PR 目標 → 最新的 `origin/release/*` → 專案 `dispatch.json` 的 `card.base` → `origin/HEAD`。都找不到就算一般風險。

## 每天怎麼用

1. 在主控台對話輸入 `/desk`：摘要列一行看有沒有「等你」；面板看「現在」那一件，第二列寫著輪到誰、要按什麼。
2. 等你 → 在面板按選項字母 → `f` 填入決策 → Enter 送出。送出後那題鎖住，等對話照決策處理並寫回卡片；回合結束卡片還沒改，面板會提醒你開卡片改或重送。
3. footer 只列這一段能做的動作；要強制做別段的事按 `m` 展開全部。
4. 派工：`g` 繼續（開始一輪流程）、`w` 審查、`s` 同步，都要按兩次確認；`y` 回覆停下來問的 Agent，`k` 停止，`l` 看最近的輸出。
5. 合併後：現在卡會列出卡片「部署步驟」與歸檔指令。有日期的待辦寫進登錄表「## 提醒」（`- YYYY-MM-DD 事項`）。
6. 卡片要改內容 → `o` 開啟 CARD.md。

## 在面板外做事

desk 只讀卡片與 git，看不到其他對話。git 與 PR 狀態會自動更新；卡片內容要有人寫回才會變。

- 建議在專案的 `CLAUDE.md` 加一條規則：改了檔案、commit、執行測試或做決策的對話，告一段落時寫回自己那張卡（狀態 60 字、下一步 40 字內，沒驗證的寫「待確認」）。
- 在這個對話裡改卡片、跑 `/desk:card`、`git commit` 或打 `!` 指令，面板會馬上重讀。
- 在面板選一件任務，之後的對話都以它為主（你打的每則都附上它的卡），再點任務名取消。
- 忘了寫：分支最近一次 commit 改到的程式比卡片新時，現在卡會提示；回到面板按 `s` 兩次同步（新對話只看卡片、`git log`、`git status`）。
- 卡片更新前先別按 `g`：繼續接的是 desk 記錄的對話，不是你另開的那個。
- 要長時間手動做某件：登錄表加一欄 `Executor`，那一列寫 `manual`，desk 就只追蹤、不派工。

## 開卡與歸檔

- 開卡：`/desk:card new <分支> <卡名> [base]`（建 worktree＋DESK 卡＋登錄表列）。
- 規格：`/desk:card spec <slug> [需求]`（讀卡與程式、問 3–5 個釐清問題，把目標／非目標／驗收情境寫進「## 規格」，關卡設 `spec：待確認規格`，此時只能同步不能派實作）→ 看過後在面板按兩次 `t`（或輸入 `/desk:card spec <slug> ok`）清關卡，就能按 `g`。審查會逐條對照驗收情境。
- 歸檔：上線後 `/desk:card archive <slug>`，或在面板點兩次「⌫ 歸檔」（卡與審查檔複製到歸檔資料夾、登錄表移到已歸檔段），再自己刪 worktree。

## 常見狀況

- **按 `g` 出現 workspace not trusted**：背景 Agent 只在「信任過的 repo」裡啟動，看的是 repo 根目錄，不是上層資料夾。處理：開新的終端機分頁 `cd <repo 根目錄> && claude`，信任提示選 **Yes, I trust this folder**，`/exit` 離開，回面板重按 `g`。不要用 `!` 跑，`!` 沒辦法回答信任提示。派工失敗不會留下任何東西，直接重按即可。
- **打了 tag 但面板沒出現 `u 上線確認`**：按 `r` 重新整理，並確認卡片關卡是 `release：…`。
