# ADR（架構決策紀錄）

> 這個資料夾放 claude-desk 寫規格時定下的重要決策，一個決策一份檔。`/desk:card spec` 寫規格時會讀各份的「決定」段，需求跟哪份矛盾就列為必問的釐清題，題目附上那份的編號與決定。

## 什麼決策要寫

寫規格時定下的決策（預設決定或使用者的回答），下面三條件都符合才寫：

- 難退回：做下去之後要改回來很費工，例如改了資料格式、檔案位置或對外的指令。
- 出乎意料：之後的人看程式或文件會想「為什麼不是另一種做法」。
- 真的有取捨：另一個選項也合理，選這個放棄了什麼說得出來。

只符合一兩條的留在卡片 Decisions 就好。實作或審查時才做的決策不寫 ADR；既有卡片的 D-nn 也不回頭補寫。

## 檔名與編號

- 檔名 `NNNN-<主題>.md`：NNNN 是四位數編號，接著這個資料夾裡最大的編號往下接（第一份是 `0001`），主題用英文小寫加連字號，例如 `0001-adr-created-by-implementation.md`。
- 同一張卡有幾份就依序往下接；編號不重用，被取代的也留著。
- 卡片 Decisions 那筆句尾寫「（ADR-NNNN）」對應到這份。

## 格式

標題一行 `# ADR-NNNN：<決策一句>`，下面三段各一段話：

```markdown
# ADR-NNNN：<決策一句>

## 背景

為什麼要做這個決定：當時的需求、限制、是哪張卡。

## 決定

選了什麼，寫成一句做得到、對得出來的話。

## 取捨

放棄了哪些選項、為什麼；選這個要付出什麼代價。
```

之後的需求推翻了某份的決定時，寫一份新的 ADR，在舊那份的標題下加一行「已被 ADR-NNNN 取代」，不刪舊檔。

## 誰建檔

寫規格這一步不建檔：規格把要建的 ADR 列進卡片「### 實作計畫」（寫背景、決定、取捨要寫什麼），確認規格後由實作照計畫建立，跟著那張卡的 PR 進 main。歸檔不寫 ADR。
