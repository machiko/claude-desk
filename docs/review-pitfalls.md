# claude-desk 審查常犯錯誤清單

> 每次審查先讀這份，逐條對照改動。回顧或審查發現過去出現過的問題時追加於檔尾，既有條目不改。

## 追加
- 規格：實作跟「### 實作計畫」寫的做法有出入（連正規式多錨一個 `$`、改成每次注入這類小差異都算）就在 History 寫明改了什麼、為什麼，不要寫「無偏離」；需求中途改了先改「## 規格」並在 Decisions 記一筆
- 測試：改 README、docs/WORKFLOW.md 或 skills/*/SKILL.md 的字句前，先 grep skills/card/tests 與 scripts/tests 有沒有斷言那段文字的 Python 測試一起改，並跑 `python3 -m unittest discover -s skills/card/tests`（CI 會跑，`claude plugin test` 不含）；AC 的測試放在 Python 那邊時，卡片「檢查」欄也要串上它
- 重複：規則搬到一處（例如某份 skill）後，README 指令表、WORKFLOW 等其他地方只寫用途並連過去，不要再寫摘要版的規則
- 註解：改了測試斷言或程式行為，同一支的 docstring／註解（AC 編號、步驟數、函式說明的位置）一起對照改；沿用別張卡的測試時，AC 編號要標是哪張卡的
- 邏輯：從登錄表挑「第一張」符合條件的卡當依據時，想一下新、舊兩張同時符合（例如上一版沒歸檔的「已發版」卡）會不會擋住或蓋掉新的；要最新的就照版號或時間挑，記下的狀態不要倒退
- 並行：重新整理很慢（claude agents、git／PR 探測、派工），要讀的檔案（卡片 worktree 裡的檔）可能在這輪跑到一半就被同回合的指令（archive --cleanup）刪掉；判斷用的資料在組快照時一起讀，不要排在重新整理尾端
- 文件：新增一個步驟或動作時，grep 文件裡「最後一項」「第 n 步之後」這類講順序的句子一起改，不要只加新段落
- 風格：Python 測試在類別中間插入方法時，對照前後空行（方法之間一行、類別之間兩行）
- 文字：改了或新增面板上看得到的提示句（檢查列、輪到你、toast）時，逐一對照會出現這句的每個情境（例如「從沒核准」與「改過」）字面是否都成立，同一件事在各處的說法要一致
- 命名：行為改了，測試名與函式名裡描述舊行為的字（asks、dialog、取消）一起改；名字是別張卡驗收情境的對應測試時，連那張卡的對照一起改，或在 History 記不改的原因
- 跨對話：$.store 是所有開著 desk 的對話共用的，回合結束要處理的待辦記下是哪個對話記的（或放對話自己的 $.state），只處理自己的，store 只記已處理過的版號，別的對話的回合結束才不會拿走它
- 版面：讓某一列變寬（多幾欄）時，對照摘要列與面板「由寬到窄試」的各版，算出改走窄版的新寬度；測試因此放不下時不要只把測試寬度調大，要在規格或 Decisions 寫明從幾欄起改走窄版、哪些字會被截
- 測試：規格寫了邊界（例如寬度 < 30 的窄畫面），就要有一支測試真的把 fixture 調到那個條件；整套測試現有的 fixture 到不了的邊界等於沒驗，寫 AC 時先確認 fixture 到得了
- 規格：修正輪實際做法跟 Decisions 寫的不同（例如截短的是左邊那句而不是提醒）時，回頭改 Decisions 或補一筆，不要只留在 History
