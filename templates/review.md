Scope: 審查這個分支自 merge-base 以來的 diff（`git diff <base>...HEAD`）
完成檢查: 自己重新執行卡片 `檢查` 欄的指令 → exit 0；不得沿用卡片或報告裡寫的結果
對照規格: 卡片「## 規格」的每一條驗收情境（見下方「規格對照」）
Done when: 審查檔 .task/REVIEW.md 整份覆寫，開頭是「規格對照」表，每條寫成「- [等級][類別] 檔案:行 — 說明」，DESK 卡 `關卡` 寫成 `review：CRITICAL <n>、HIGH <n>、MEDIUM <n>、LOW <n>；<一句結論>`，四個數字都要有
Report: 審查檔本身；卡片「狀態」一句話

分級：
- CRITICAL：資安、資料外洩、資料毀損、機密或個人資料進版控
- HIGH：實際的 bug、漏做授權或資料範圍檢查、驗收情境沒做到或沒測到
- MEDIUM：可維護性、命名、重複
- LOW：風格

規格對照（每次審查都要做，寫在審查檔最前面）：
- 先讀卡片「## 規格」：目標、非目標、驗收情境。審查是看「程式有沒有做到規格」，不只是「程式本身寫得好不好」。
- 逐條寫成表格：`| AC-n | 做到／沒做到／沒測到／無法判斷 | 依據（檔案:行 或 測試名） |`。
  - 做到：程式有實作，且有測試驗證到「則」那一欄的結果。
  - 沒做到：程式沒有實作這條，或行為與「則」不符 → 另列一條 `- [HIGH][規格] 檔案:行 — AC-n …`。
  - 沒測到：程式看起來有做，但沒有測試，或測試沒有斷言到「則」的結果（只跑過、沒驗結果也算） → 另列 `- [HIGH][測試] … — AC-n …`。
  - 無法判斷：規格寫得無法驗證（「則」不可觀察、互相矛盾） → 另列 `- [MEDIUM][規格] — AC-n 無法驗證：…`，並在卡片「等你」請人釐清，不要自行猜測需求。
- 做了「非目標」或 Scope 外的事 → `- [MEDIUM][範圍] …`；若碰到授權、資料範圍、個人資料，照原本分級。
- 卡片沒有「## 規格」段：表格只寫一行「卡片無規格段，略過規格對照」，不因此扣分。
- 複審只重看上一輪「沒做到／沒測到」的 AC，其餘沿用上一輪結果。

過關時要讓人在面板上看得到下一步（不會有人去翻審查檔）：
- CRITICAL＋HIGH 為 0、但有 MEDIUM：卡片「等你」寫成一題可按的決策，例如 `審查 MEDIUM 1 條（<一句摘要>）怎麼處理：A) 不修，記錄原因 B) 修掉 C) 改規格`；多條 MEDIUM 合成一題，摘要寫最重要的一條。選項裡不要用「；」。
- 「下一步」寫人接下來實際要做的事（40 字內），例如 `決定 MEDIUM 後 push、開 PR`；沒有 MEDIUM 就寫 `可開 PR：push 後開 PR 到 release 線`。不要寫「工作桌依數字分流」這類內部說明。
- 沒過關（有 CRITICAL／HIGH）時「等你」留 無，工作桌會自動派修正。

工作桌依數字分流：CRITICAL＋HIGH 為 0 就過關；否則自動派修正，最多兩輪，第三次還有就停下來找人。

環境約束（違反即視為審查無效）：
- 這是新的對話，不接續執行者、不參考執行者的結論；只看任務檔、diff 與自己執行的完成檢查輸出。
- 不得自建資料庫或容器、不得改 port、不得啟動或重建容器。
- 不改程式、不 commit；發現問題寫進審查檔，修正由下一輪處理。

複審（修正後的第 2、3 次審查）：只看上次審查之後的 diff，先讀上一份審查檔；只判斷上次的 CRITICAL／HIGH 修好沒、新 diff 有沒有新問題，已列過的 MEDIUM／LOW 與標「不修」的不要再提。

資安審查（高風險改動才會有，寫 .task/SECURITY.md）：只看授權與資料範圍、輸入驗證、SQL／XSS、個人資料外洩、機密金鑰、檔案路徑、外部呼叫。
